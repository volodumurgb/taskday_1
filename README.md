# API складського обліку

REST API на Django та Django REST Framework для обліку товарів, складів і руху запасів у межах компанії. Сервер обчислює залишки з історії операцій через Django ORM. Вартість запасу дорівнює залишку, помноженому на поточну базову ціну.

## Запуск через Docker

```sh
docker compose up --build
```

Compose запускає PostgreSQL і Redis, очікує їхньої готовності та застосовує міграції перед запуском API. Адреса сервера — http://localhost:8000/api/. Дані PostgreSQL зберігаються в іменованому томі.

## Локальний запуск

З кореня репозиторію:

```sh
python -m pip install -r requirements.txt
cd inventory_api
python manage.py migrate
python manage.py runserver
```

За замовчуванням локальний запуск використовує SQLite та кеш у пам’яті. У Docker Redis зберігає лічильник операцій і кеш зведеного звіту.

## Маршрути API

| Метод і маршрут | Дія |
| --- | --- |
| `POST /api/auth/register/` | Створити обліковий запис і нову компанію. Поля: `username`, `password`, `company_name` та необов’язковий `email`. |
| `POST /api/auth/login/`, `POST /api/auth/logout/` | Відкрити або закрити сесію. |
| `POST /api/auth/password-reset/` | Запросити посилання для скидання пароля за адресою `email`. У конфігурації для розробки лист з’являється в консолі Django. |
| `GET`, `POST /api/warehouses/` | Переглянути або створити склади. |
| `GET`, `PUT`, `PATCH`, `DELETE /api/warehouses/{id}/` | Переглянути, змінити або видалити склад. Склад із записами руху захищений від видалення. |
| `GET`, `POST /api/products/` | Переглянути або створити товари. |
| `GET`, `PUT`, `PATCH`, `DELETE /api/products/{id}/` | Переглянути, змінити або м’яко видалити товар. |
| `GET`, `POST /api/transactions/` | Переглянути або записати рух товару. |
| `GET /api/transactions/{id}/` | Переглянути окрему операцію. |
| `GET /api/reports/summary/` | Отримати сумарну вартість запасів по складах. |
| `GET /api/reports/stock-export/?format=json` | Експортувати залишки у JSON. Для CSV використовуйте `?format=csv`. |

Після входу клієнт використовує cookie сесії. Для запитів, які змінюють дані в межах сесії, передавайте CSRF-токен. Списки товарів, складів і транзакцій мають пагінацію по 20 записів.

У списку товарів `?search=...` шукає за назвою або SKU, а `?ordering=-total_stock` і `?ordering=base_price` сортують за залишком та ціною. Для історії руху доступні фільтри `transaction_type`, `warehouse` (джерело або одержувач), `source_warehouse`, `destination_warehouse`, `occurred_at__gte` та `occurred_at__lte`.

## Правила складського обліку

- `IN` потребує склад-одержувач, `OUT` — склад-джерело, `TRANSFER` — два різні склади.
- Кількість має бути більшою за нуль. Списання чи переміщення потребує достатнього запасу на складі-джерелі.
- За одну хвилину працівник може створити щонайбільше 50 операцій. Зведений звіт кешується на п’ять хвилин, а після запису операції кеш очищується.
- Після списання нижче мінімального запасу Django формує сповіщення для адресатів, заданих у `ADMINS`. Для доставки поштою потрібне налаштування поштового сервера.
